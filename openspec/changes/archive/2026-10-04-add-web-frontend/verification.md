# add-web-frontend 浏览器走查记录（2026-10-04）

环境：Windows，Node v24.18.0 + pnpm 11.20.0；后端 `cargo run -p server`（127.0.0.1:3001，bigmodel::glm-5.3-flash）；前端 Vite dev server（http://localhost:5173，AI SDK `ai@7.0.127` + `@ai-sdk/react@4.0.130`）。走查工具：ZCode IAB 浏览器自动化（DOM snapshot + 节点点击）。

## spec `web-chat-ui` 各 Scenario 对照

### 提交用户消息并看到对话历史
- 提交一条消息：输入"你好，请用一句话介绍你自己"点击发送 → 用户消息立即出现，模型流式回复自我介绍。**通过**
- 空消息不发送：空输入框点击 Submit → 无请求、无报错、界面不变。**通过**
- 生成期间再次提交被阻止：流式期间输入"再写一首"按 Enter → 无新请求无新消息，页脚显示"已提交…/生成中…"，按钮为 Stop 态。**通过**（补丁：生成中 Enter 现在会 preventDefault 保留草稿）

### 助手回复以流式文本渲染
- 流式追加：请求"从1数到30"在输出 "1 2 3 … 27" 过程中点击停止，截断内容即为增量渲染证据。**通过**
- 多步回复顺序衔接：工具调用后模型继续输出文本（"计算结果：2 + 3 = 5 ✅"），与工具块同消息顺序渲染。**通过**

### 工具调用以独立区块渲染
- 工具进行中：流式期间工具块以 "Running" 徽标呈现（add Completed/Error 终态亦实测）。**通过**
- 工具成功："请用 add 工具计算 2 + 3" → 工具块 Completed，自定义渲染 `2 + 3 = 5`。**通过**
- 工具失败："计算 9223372036854775807 + 1"（int64 溢出）→ 工具块 Error 状态展示错误文本，对话不中断，模型继续解释溢出原因。**通过**

### 回复元数据与结束状态可见
- 正常完成：助手消息尾部"已完成 · 2 步"。**通过**
- 步数上限：`AGENT_MAX_STEPS=1` 启动后端 → "已达步数上限 · 1 步"（橙色可区分）。**通过**

### 用户可以停止生成
- 中途停止：数数到 27 时点 Stop → 已渲染内容保留，出现"已停止生成"标记，输入恢复。**通过**

### 错误可见且不破坏对话
- 服务端错误事件：流 `error` 事件（后端日志路径）未在本次实测中单独触发，但传输层错误路径已覆盖（下条）。**通过（间接）**
- 后端不可达：停后端发消息 → `role=alert` 横幅"请求失败：Failed to fetch"，历史保留；重启后端后重发"从1数到5"成功回复。**通过**

### 后端地址可配置
- 默认直连本地服务端：未设置 VITE_API_BASE，直连 3001 正常（CORS 已放行 5173）。**通过**
- 后端未启动：刷新页面 → 徽标"后端不可达" + 提示横幅（期望地址 + `cargo run -p server` 指引）；启动后点击徽标重新探测恢复"后端已连接"。**通过**

## 额外说明

- AI SDK 版本：按用户决策采用最新 v7 线（`ai@^7` + `@ai-sdk/react@^4`），v7 客户端解析后端 v1 UI Message Stream 已由实测确认（另有后端侧 `scripts/ai-sdk-check` 固定 `ai@7.0.127` 的协议验证佐证）。
