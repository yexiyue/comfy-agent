# 01 · 项目启动：把骨架立起来

> 系列第 1 篇。前置阅读：[00-大纲.md](00-大纲.md)。
> 本篇不接 LLM、不碰 ComfyUI——只把项目骨架立起来，让后面 23 篇都有地方落笔。

## 目标

- 建立教程项目 `comfy-agent`，理解每个依赖为什么出现在 `Cargo.toml` 里
- 配置好环境变量管理（`.env`）和日志（`tracing`）
- 跑通第一个可执行文件，形成"改代码 → cargo run → 看日志"的循环

## 动手

### 1. 环境检查

```bash
rustc --version   # 需要 1.85+（edition 2024）；本教程在 1.98 上验证
cargo --version
```

ComfyUI **本篇不需要**，到第 08 篇再启动它。但 API key 现在就要：

- 到 [bigmodel.cn](https://bigmodel.cn) 控制台创建 API key（智谱 GLM，本教程主力模型）

### 2. 建项目

在任意目录（建议和本仓库平级）：

```bash
cargo new comfy-agent
cd comfy-agent
```

### 3. Cargo.toml

替换为以下内容（**本篇代码已在 Rust 1.98 / edition 2024 下编译验证**）：

```toml
[package]
name = "comfy-agent"
version = "0.1.0"
edition = "2024"

[dependencies]
genai = "0.7.0-rc.1"                                     # LLM 多厂商适配层（02 篇开始用）
tokio = { version = "1", features = ["full"] }           # 异步运行时
serde_json = "1"                                          # 工具 schema / 参数都是 JSON
dotenvy = "0.15"                                          # .env 加载
anyhow = "1"                                              # 错误类型统一
tracing = "0.1"                                           # 结构化日志（17 篇升级为观测主干）
tracing-subscriber = { version = "0.3", features = ["env-filter"] }
```

每个依赖的"寿命"：`tokio`/`anyhow`/`tracing` 全程使用；`genai` 从 02 篇用到最后；
`serde_json` 在 04 篇工具调用时开始挑大梁；`dotenvy` 本篇就用。

### 4. 环境变量：.env

在项目根目录创建 `.env`（**永远不进 git**）：

```bash
# 国内智谱 key（open.bigmodel.cn）。genai 里 bigmodel 适配器读这个名字
BIGMODEL_API_KEY=你的key

# 教程默认模型。bigmodel:: 前缀强制走国内端点；裸写 glm-* 会走国际版 Z.ai（ZAI_API_KEY）
MODEL=bigmodel::glm-4.6

# 日志级别（RUST_LOG 语义，Rust 侧标准）
RUST_LOG=comfy_agent=debug,genai=warn
```

> **为什么是 `bigmodel::`？** genai 按模型名前缀推断厂商：`gpt-*` → OpenAI、
> `glm-*` → 智谱国际版 Z.ai（读 `ZAI_API_KEY`）。国内 open.bigmodel.cn 的 key 要用
> `bigmodel::` 命名空间强制指定适配器（读 `BIGMODEL_API_KEY`）。两套端点账号不通用，
> 这是国内用户最常见的第一个坑。

`.gitignore` 加一行：

```
.env
```

### 5. main.rs

```rust
use anyhow::Result;

#[tokio::main]
async fn main() -> Result<()> {
    // 从项目根目录加载 .env（已设置的环境变量优先，不覆盖）
    dotenvy::dotenv().ok();

    // 日志：默认用 RUST_LOG，没有则退回这个默认级别
    tracing_subscriber::fmt()
        .with_env_filter(
            tracing_subscriber::EnvFilter::try_from_default_env()
                .unwrap_or_else(|_| "comfy_agent=debug".into()),
        )
        .init();

    let model = std::env::var("MODEL").unwrap_or_else(|_| "glm-4.6".into());
    tracing::info!(model, "comfy-agent skeleton ready");

    Ok(())
}
```

两个值得注意的细节：

- `#[tokio::main]` 现在就加上：genai 是纯异步 API，所有调用都在 `.await` 上，
  从第一天起就是 async 项目，避免后面搬家。
- `tracing::info!(model, ...)` 是**字段式日志**——`model` 作为结构化字段而不是文本拼接。
  这是为 17 篇的观测体系埋的种子：到时候日志要进 SQLite 做指标，结构化字段直接就是列。

### 6. 预埋模块目录

```bash
mkdir -p src/{llm,agent,comfy,server,observ,memory} workflows
```

```
comfy-agent/
├── Cargo.toml
├── .env
├── src/
│   ├── main.rs
│   ├── llm/  agent/  comfy/  server/  observ/  memory/   # 空目录，git 不跟踪，随用随建文件
└── workflows/          # 08 篇起：ComfyUI 工作流 + 槽位声明
```

### 7. 跑起来

```bash
cargo run
```

预期输出（时间戳略有不同）：

```
2026-10-03T08:12:34.567890Z  INFO comfy_agent: comfy-agent skeleton ready model="bigmodel::glm-4.6"
```

看到 `model="bigmodel::glm-4.6"` 说明 `.env` 读取、日志初始化全部就位。

## 产出与验收清单

- [ ] `cargo run` 无报错，日志里 `model` 字段值来自 `.env`
- [ ] `cargo build` 无 warning
- [ ] `.env` 不在 `git status` 的待跟踪列表里

## 练习

1. 把 `RUST_LOG` 环境变量临时改成 `comfy_agent=trace` 再 `cargo run`（不用改 `.env`，
   直接 `RUST_LOG=comfy_agent=trace cargo run`），体会 env-filter 的优先级。
2. 给 `main.rs` 加命令行参数支持：`cargo run -- --model glm-4.6` 可以覆盖 `.env` 里的
   MODEL（提示：`std::env::args()`，无需引入 clap——到 14 篇有更复杂的参数需求再说）。
